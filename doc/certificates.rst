Работа с сертификатами открытых ключей
======================================

.. contents:: Содержание
   :depth: 3

Структуры, используемые при работе с сертификатами
--------------------------------------------------

Структура запроса на сертификат открытого ключа `ak_request` содержит следующие поля:

* `struct verifykey vkey` - открытый ключ

* `struct request_opts opts` - параметры запроса на сертификат

Структура сертификата открытого ключа `ak_certificate` содержит следующие поля:

* `struct verifykey vkey` - открытый ключ

* `struct certificate_opts opts` - параметры сертификата


Структура секретного ключа алгоритма выработки электронной подписи ГОСТ Р 34.10-2012 `ak_signkey` содержит следующие поля:

* `struct skey key` - структура секретного ключа

* `struct hash ctx` - структура бесключевой функции хеширования

* `ak_uint8 verifykey_number[32]` - номер открытого ключа, выработанного из данного секретного ключа


Структура параметров сертификата открытого ключа `ak_certificate_opts` содержит следующие поля:

* `ak_uint32 version` - версия сертификата (по-умолчанию, работает с v3, для этого используется значение 2)

* `ak_tlv subject` - имя владельца сертификата

* `ak_uint8 signature[128]` - значение электронной подписи (используется только при чтении созданного ранее сертификата)

* `ak_tlv issuer` - имя эмитента (центра сертификации)

* `struct time_interval time` - временной интервал действия сертификата

* `ak_uint8 serialnum[32]` - серийный номер сертификата (при экспорте значение вырабатывается в процессе выработки сертификата, при импорте - считывается из asn1 дерева)

* `ak_uint32 serialnum_length` - длина серийного номера

* `ak_uint8 issuer_number[32]` - номер ключа эмитента

* `ak_uint32 issuer_number_length` - длина ключа эмитента

* `ak_uint8 issuer_serialnum[32]` - серийный номер эмитента

* `ak_uint32 issuer_serialnum_length` - длина серийного номера сертификата эмитента

* `bool_t created` - флаг того, создан ли сертификат, используется только при импорте сертификатов

* `struct ext_ca` - структура основных ограничений
  
  * `bool_t is_present` - используются ли ограничения
  
  * `bool_t value` - разрешено ли порождать цепочки сертификации
  
  * `ak_uint32 pathlenConstraint` - количество промежуточных сертификатов в цепочке сертификации

* `struct ext_key_usage` - структура облости применения
  
  * `bool_t is_present` - задана ли область применения

  * `ak_uint32 bits` - набор бит, описывающих область применения открытого ключа

* `struct ext_subjkey` - структура идентификатора ключа 
  
  * `bool_t is_present` - используется ли идентификатор ключа

* `struct ext_authoritykey` - структура идентификатора ключа эмитента
  
  * `bool_t is_present` - используется ли идентификатор ключа эмитента

  * `bool_t include_name` - используется ли расширенное имя эмитента

* `struct ext_secret_key_number` - структура номера секретного ключа
  
  * `bool_t is_present` - используется ли номера секретного ключа

  * `ak_uint8 number[32]` - уникальный номер секретного ключа, соответствующий данному открытому ключу


Создание сертификата из запроса на сертификат
---------------------------------------------

Функция:
::

  static ak_certificate aktool_key_verify_ca(ak_certificate ca_cert, const char *filename)

Данная функция позволяет считать сертификат ключа УЦ. Параметры функции:

* `ak_certificate ca_cert` - структура сертификата открытого ключа

* `const char *filename` - имя файла с сертификатом

Возвращаемое значение: структура сертификата открытого ключа `ak_certificate` или `NULL`.

Функция:
::

  int ak_request_import_from_file(ak_request req, const char *filename)

Данная функция позволяет импортировать запрос на сертификат. Параметры функции:

* `ak_request req` - структура запроса на сертификат открытого ключа

* `const char *filename` - имя файла с сертификатом

Возвращаемое значение: код ошибки типа `int`. Если функуция отработала успешно возвращается `ak_error_ok`.

Функция:
::

  int ak_certificate_export_to_file(ak_certificate subject_cert, ak_signkey issuer_skey, ak_certificate issuer_cert, ak_random generator, char *filename, const size_t size, export_format_t format)

Данная функция позволяет подписать и сохранить сертификат. Параметры функции:

* `ak_certificate subject_cert` - структура создаваемого сертификата открытого ключа

* `ak_signkey issuer_skey` - структура секретного ключа, с помощью которого подписывается создаваемый сертификат

* `ak_certificate issuer_cert` - структура сертификата открытого ключа, соответствующая секретному ключу подписи

* `ak_random generator` - структура генератора псевдо-случайных чисел, используемый для подписи сертификата

* `char *filename` - имя файла, в который будет экспортирован ключ

* `const size_t size` - размер области памяти, в которую будет помещено имя файла

* `export_format_t format` - формат, в котором сохраняются данные (`asn1_der_format` или `asn1_pem_format`)

Возвращаемое значение: код ошибки типа `int`. Если функция отработала успешно возвращается `ak_error_ok`.

Пример
~~~~~~

::

    struct certificate ca_cert;
    ak_certificate ca_cert_ptr = NULL;
    ak_request req;
    struct signkey issuer_skey;
    ak_random generator;
    ca_cert_ptr = aktool_key_verify_ca(&ca_cert, "example.crt") // считываем сертификат ключа УЦ
    ak_request_import_from_file(&req, "example2.crt") //импорт запроса на сертификат
    ...
    ak_certificate_export_to_file(&ca_cert, &issuer_skey, ca_cert_ptr, generator, // подпись запроса и сохранение сертификата
        "example3", 8, asn1_pem_format);
    ak_certificate_destroy( &ca_cert );

Создание p7b контейнера
-----------------------

Функция:
::

  ak_asn1 ak_certificate_new_p7b_skeleton( ak_asn1 *sequence )

Данная функция позволяет создать новый (пустой) p7b контейнер. Параметры функции:

* `ak_asn1 *sequence` - указатель, в который помещается ссылка на прелполагаемый список сертификатов

Возвращаемое значение: В случае успеха возвращается указатель на вершину созданного asn1 дерева или `NULL`.

Функция:
::

  int ak_asn1_import_from_file( ak_asn1 asn, const char *filename, export_format_t *format )

Данная функция позволяет импортировать ASN.1 дерево из файла, содержащего der-последовательность.

* `ak_asn1 asn` - уровень ASN.1, в который помещается считываемое значение

* `const char *filename` - имя файла, в котором содержится der-последовательность

* `export_format_t *format` - если указатель не равен NULL, то по даному адресу размещается формат считанных данных

Возвращаемое значение: код ошибки типа `int`. Если функция отработала успешно возвращается `ak_error_ok`.

Функция:
::

  int ak_certificate_import_from_asn1( ak_certificate subject_cert, ak_certificate issuer_cert, ak_asn1 root )

Данная функция позволяет импортировать открытый ключ асимметричного преобразования из сертификата открытого ключа, представленного в виде asn1 дерева. Параметры функции:

* `ak_certificate subject_cert` - контекст сертификата открытого ключа

* `ak_certificate issuer_cert` - контекст сертификата ключа проверки подписи

* `ak_asn1 root` - указатель на вершину asn1 дерева

Возвращаемое значение:

-------------------------------------------------------------------------------------

Функция:
::

  ak_asn1 ak_certificate_get_sequence_from_p7b_asn1(ak_asn1)

Данная функция позволяет получить последовательности сертификатов из p7b контейнера. Параметры функции:

* `ak_asn1 root` - структура корня asn1 дерево, содержащее p7b-контейнер

Возвращаемое значение: в случае успешной проверки, функция возвращается указатель на уровень asn1 дерева,

Функция:
::

  int ak_certificate_opts_create(ak_certificate_opts opts)

Данная функция позволяет присвоить значения по-умолчанию для опций сертификата. Параметры функции:

* `ak_certificate_opts opts` - структура параметров сертификата открытого ключа.

Возвращаемое значение: код ошибки типа `int`. Если функция отработала успешно возвращается `ak_error_ok`.

Работа с репозиторием
---------------------

Путь к каталогу хранения доверенных сертификатов хранится в глобальной переменной `ca_repository_path`.
По умолчанию ему присваивается значение, определенное при конфигурации библиотеки.
изменить его можно путем вызова `cmake -D AK_CA_PATH="каталог"`, а также при помощт функции:

Функция:
::

  int ak_certificate_set_repository( const char *path )

Данная функция позволяет установить путь к каталогу, в котором хранятся доверенные сертификаты,
изменив значение перменной `ca_repository_path`. Параметры функции:

* `path` - путь к каталогу хранения доверенных сертификатов.

Возвращаемое значение: код ошибки типа `int`. Если функция отработала успешно возвращается `ak_error_ok`.
Возможные значения ошибок:

* `ak_error_null_pointer (-2)` - в параметре path содержится нулевой указатель.

* `ak_error_not_directory (-24)` - в параметре path был передан несуществующий путь, либо путь не до директории.


Функция:
::

  const char * ak_certificate_get_repository( void )

Данная функция позволяет получить из глобальной переменной `ca_repository_path` путь к каталогу,
в котором хранятся доверенные сертификаты.

Возвращаемое значение: путь к каталогу с доверенными сертификатами.

Примеры
-------
Создание запроса на подпись сертификата
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Исходный текст примера находится в файле ``example-g06n01.c``.

В примере использовались следующие переменные
* `struct certificate cert` - сертификат.

* `time_interval_t tm` - временной интервал для задания срока действия.

* `ak_oid oid_of_target` - идентификатор и данные ключа.

* `ak_pointer key` - секретный ключ.

* `ak_oid curve` - эллиптическая кривая.

* `ak_random generator` - генератор для выработки случайного секретного ключа.

* `ak_oid oid_of_generator` - идентификатор и данные генератора.

* `ak_tlv subject` - информация о владельце сертификата, хранящаяся в узле ASN1 дерева.

1. Создается ключ с помощью `ak_oid_new_object`. В качестве идентификатора объекта, передается идентификатор
   с именем ``sign256`` (алгоритм ГОСТ Р 34.10-2012).
2. Задается кривая для ассиметричных ключей с именем ``cspa`` при помощи `ak_signkey_set_curve`.
3. Вырабатывается случайный секретный ключ с помощью `oid_of_target->func.first.set_key_random( key, generator )`.
   В качестве генератора, для примера, был взят объект с порядковым номером 1 (lcg).
4. Устанавливается срок действия (в данном примере 10 дней) с помощью
   `ak_skey_set_validity( key, tm.not_before, tm.not_after )`.
5. Инициализируется контекста открытого ключа асимметричного криптографического алгоритма и
   вычисляется его значения (а именно точка эллиптической кривой) при помощи
   `ak_verifykey_create_from_signkey( &cert.vkey, key )`.
6. Создается узел ASN1 дерева, содержащий пустую последовательность, hпи помощи `ak_tlv_new_sequence()`.
   В этом узле будет хранится информация о владельце сертификата. Информация в узел добавляется при
   помощи `ak_tlv_add_string_to_global_name( subject, "common-name", "Example Name")`. В данном примере
   добавляется ``common-name (CN)``. Другие данные можно добавить по аналогии.
7. Создается запрос на сертификат при помощи `ak_request_export_to_file( (ak_request)( &cert ), key, generator, "req.csr",
   0, asn1_pem_format )`.
8. Секретный ключ сохраняется в файл при помощи
   `ak_skey_export_to_file_with_password(key, NULL, 0, "private.key", 0, asn1_pem_format)`. В данном случае
   используется пустой пароль, так как это пример.

Создание корневого самоподписанного сертификата
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Исходный текст примера находится в файле ``example-g06n02.c``.

Пример похож на предыдущий, за исключением того, что в 7 пункте явно указывается то, что данный сертификат
может подписывать другие сертификаты. Также вместо `ak_request_export_to_file()` используется
`ak_certificate_export_to_file( &cert, key, &cert, generator, "root_cert.crt", 0, asn1_pem_format )` для
создания самоподписанного сертификата.

Подпись запроса на сертификат
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
Исходный текст примера находится в файле ``example-g06n03.c``.

В данном примере подразумевается, что в директории с исполняемым файлом находится:

1. сертификат в файле ``root_cert.crt``, который может подписывать другие сертификаты.

2. секретный ключ в файле ``root_private.key``, соответствующий сертификату из файла ``root_cert.crt``.

3. Запрос на создание сертификата в файле ``req.csr``.

Для выполнения этих условий достаточно выполнить примеры ``example-g06n01.c`` и ``example-g06n02.c``.
.. `

В примере использовались следующие переменные

* `ak_oid oid_of_generator`- идентификатор и данные генератора.

* `struct signkey issuer_skey` - секретный ключ, соответствующий коневому сертификату.

* `struct certificate ca_cert` - корневой самоподписанный сертификат.

* `struct certificate cert` - сертификат, созданный в результате подписи запроса.

* `ak_random generator` - генератор случайных чисел, используемый для подписи сертификата.

1. Считывается корневой сертификат при помощи `ak_certificate_import_from_file( &ca_cert, NULL, "root_cert.crt" )`
   из файла ``root_cert.crt``.
2. Проверяется, что сертификат может подписывать другие сертификаты и проверять подписи с помощью
   `ca_cert.opts.ext_ca.is_present` (расширение `Basic Constraints` (oid: 2.5.29.19)) и `
   ca_cert.opts.ext_key_usage.bits&bit_keyCertSign`.
3. Считывается секретный ключ корневого сертификата при помощи
   `ak_skey_import_from_file( &issuer_skey, sign_function, "root_private.key" )`.
4. Считывается запрос на сертификат при помощи `ak_request_import_from_file( (ak_request)( &cert ), "req.csr" )`.
5. Устанавливается срок действия сертификата.
6. Подписывается запрос и сертификат сохраняется в файл при помощи
   `ak_certificate_export_to_file( &cert, &issuer_skey, &ca_cert, generator, "cert.crt", 0, asn1_pem_format )`.
   Предварительно создается генератор (в данном случае ``lcg``) при помощи `ak_oid_new_object(oid_of_generator)`.
